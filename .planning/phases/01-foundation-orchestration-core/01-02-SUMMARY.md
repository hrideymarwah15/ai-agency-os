## Decisions Made

- Trigger-tamper tests assert `sqlalchemy.exc.DBAPIError` (not `ProgrammingError` as the plan wrote) — verified against installed SQLAlchemy: asyncpg `RaiseError` → `PLPGSQLError` → `PostgresError` maps to `DBAPIError`; the message `audit_logs is append-only` is the meaningful contract
- `record()`'s `correlation_id` made optional with uuid4 generation — required by the plan's own `test_default_correlation_id_generated`; compatible with existing callers (api/auth.py passes it explicitly)
- Test cleanup via `TRUNCATE` — the whole point of the trigger is that DELETE fails; TRUNCATE (statement-level) is not blocked by the row-level trigger, so it is safe for test-only cleanup
- Clear-filter link shown only when a filter is active; the filter input is never prefilled — correlation IDs are never echoed to the page
