## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| agent workflow → approval gate | LLM-produced context crosses here; the decision must be code-structured, never LLM text |
| browser → /approvals actions | owner-only mutating surface; CSRF and session crossing here |
| sweeper → paused graphs | automated expiry decisions resume workflows |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | approval gate (prompt injection into approval decisions) | mitigate | Gate payloads are structured state (amount, entity_type, entity_id, details) built by code from business objects — never LLM free text; LLM output never sets the decision value; queue UI renders fields not prose (UI-SPEC Security-Adjacent); canary-string test asserts raw LLM text never reaches the page |
| T-03-02 | Spoofing | resume orchestration (thread_id poisoning / hijacked resume) | mitigate | thread_id is a UUID generated at gate time, stored on the approval_requests row; resume uses ONLY the row's thread_id — never a client-supplied thread_id; no resume without a matching PENDING row |
| T-03-03 | Spoofing | approve/reject/escalate (CSRF) | mitigate | SameSite=Lax cookie + Origin header check on all mutating POSTs (403 on mismatch); all actions audited with actor="owner" |
| T-03-04 | Tampering | interrupt gate (swallowed interrupt bypasses pause) | mitigate | Never wrap interrupt() in try/except (Pitfall 2, code-review gate); interrupt called FIRST with deterministic ordering (Pitfall 1); side effects only in proceed/cancel nodes run after resume |
| T-03-05 | Elevation | duplicate side effects on resume (double audit rows / double sends) | mitigate | Side effects live downstream of interrupt; the request row + approval_requested audit live in the run-once prepare_request node BEFORE the gate; create_request upserts by thread_id (idempotent) — tests assert exactly one PENDING row AND exactly one approval_requested audit row |
| T-03-06 | Spoofing | sweeper auto-expiry (stale request auto-rejected) | mitigate | Expiry is an explicit reject with reason "timeout", audited; expires_at from settings; sweeper runs on the heartbeat-monitored scheduler (plan 04) so silent sweeper death is itself alerted |
</threat_model>
