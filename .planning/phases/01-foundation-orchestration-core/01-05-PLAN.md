## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| app → external domains | robots + rate-limit gate sits here; untrusted remote content crosses back |
| send gate → recipient | consent/suppression/cap decisions cross here |
| public internet → /unsubscribe | token-gated public mutation endpoint |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Tampering | fetch path (robots/rate-limit bypass) | mitigate | CompliantHTTPClient is the ONLY fetch door (D-15); robots checked before any request; parse failure → deny-by-default + audit; rate limit keyed per domain |
| T-05-02 | Spoofing | /unsubscribe (unsubscribing others / token forgery) | mitigate | itsdangerous URLSafeTimedSerializer signed token (7d TTL, tamper-proof); no email parameter in URL — identity comes from the signed token only |
| T-05-03 | Tampering | send gate (bypassing consent/caps) | mitigate | check_send is the only send door; caps via atomic reserve_outreach (plan 04); every block audited send_blocked; Phase 3 sends MUST route through it |
| T-05-04 | Information Disclosure | suppression/consent data (email enumeration) | mitigate | No read endpoints on suppression/consent — services are internal; public surface only inserts via signed token; no existence-revealing responses |
| T-05-05 | Spoofing | robots.txt content (malicious directives) | mitigate | deny-by-default posture: anything unparseable or hostile blocks the fetch; audit record for every default-deny decision |
</threat_model>
