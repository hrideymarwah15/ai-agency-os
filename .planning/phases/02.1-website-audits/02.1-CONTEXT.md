## Phase Boundary

SPIDR slice after Phase 02 (Discovery): per-lead website intelligence audits. Given a lead's
website URL, the system runs performance (INP-based Core Web Vitals), accessibility, SEO,
and mobile assessments; detects tech stack, CMS, hosting provider, and analytics presence;
finds broken links, missing forms, and conversion-flow gaps; stores results per lead with
timestamped history. Owner views audit results per lead. Reuses the Phase 2 compliant fetch
door (robots deny-by-default + token bucket + api_hosts exemptions) for all fetching.

Discovery (LEAD-*) and opportunities/scoring (OPP-*, SCOR-*) are separate slices (02 and 02.2).

<decisions>
## Implementation Decisions

### Crawling & Compliance (AUDT-01, D-13/D-15/D-30 carry-over)
- **D-32:** All website fetches go through the compliant HTTP client factory
  (`backend/tools/http_client.py`): robots deny-by-default + per-domain token bucket with
  jitter + api_hosts exemption set. No raw httpx/requests fetches of audit targets anywhere.
- **D-33:** Playwright is re-added (D-04/D-30) for JS-rendered audits ONLY where needed
  (e.g., tech-stack/analytics script detection requires rendered DOM); static analysis of
  HTML/headers/CSS/JS assets covers the rest. Playwright tests are optional-skip on CI if
  browsers unavailable (pytest.mark.skipif pattern); zero-network unit tests remain the core.
- **D-34:** INP-based Core Web Vitals (AUDT-01): LCP/INP/CLS/TTFB measured or estimated from
  static analysis + observed timings; FID is NOT used (locked in Phase 1 requirements).
  Lab-style estimates are labeled as estimates with methodology in the stored report.

### Audit Scope & Storage (AUDT-01..04)
- **D-35:** Audit = one persisted `website_audits`-equivalent row per lead per run with
  timestamped history (AUDT-04): performance/accessibility/SEO/mobile scores (0-100),
  Core Web Vitals values, tech stack list, CMS, hosting, analytics presence, broken links
  list (with status codes), missing forms/conversion-flow gaps, crawled_at, audit version.
- **D-36:** Scores are computed by deterministic rules (no LLM) from measurable signals:
  headers, resource sizes, asset counts, HTML structure, meta tags, structured data,
  robots/sitemap presence, link checks via the compliant client. LLM is NOT used for scoring.
- **D-37:** Broken-link checking (AUDT-03): extract internal links from parsed HTML, check a
  capped sample (config) through the compliant client with per-domain token bucket; link
  statuses stored; external link checking capped/optional to respect rate limits.
- **D-38:** Tech stack/CMS/hosting/analytics detection (AUDT-02): deterministic signature
  matching (HTML markers, script/src patterns, header signatures, generator meta, cookie
  names) over a signature table; detection per rendered+static analysis; confidence recorded.
- **D-39:** Audit history: multiple audits per lead over time; newest-first list; history
  page/route per lead; re-audit trigger (manual) creating a new audit run row.

### Trigger & UI (AUDT-01, DASH-02 family)
- **D-40:** Audit trigger: owner-triggered per lead (manual), enqueued via outbox (Phase 2
  pattern) → worker executes the audit pipeline; runs appear in the dashboard/audit list.
  Queue with heartbeat/sweeper patterns from Phase 1 (scheduler.py).
- **D-41:** UI: Jinja2 SSR pages — lead audit list + per-audit detail (scores, CWV table,
  tech stack, broken links, gaps); reuse Phase 1/2 design tokens and page patterns; zero JS.
- **D-42:** Sanitization carry-over (CMP-06/D-27): all scraped content routed through
  `backend/services/discovery/sanitize.py` before storage/rendering; `|safe` forbidden.

### Research Resolutions (02.1-RESEARCH.md open questions)
- **D-43 (A3):** Robots+Playwright interplay: robots pre-check + one bucket acquire governs
  whether the page is rendered at all (deny-by-default respected before launching any
  browser); rendered analysis is single-page scope. No per-request route gating.
- **D-44 (A2):** INP measured via scripted-interaction event-timing with long-task proxy
  fallback; every CWV value stored with a methodology label (lab estimate vs measured);
  FID never used.
- **D-45:** External broken-link checking capped at 5 links per audit (config,
  0 = off); internal links capped at 20.
- **D-46:** Legacy dead `Audit` model left untouched (out of scope).

<specifics>
## Specific Ideas

- CWV estimation: LCP/INP/CLS need real rendering; with Playwright available, use
  PerformanceObserver/WebVitals JS on the rendered page; without, store estimated/missing
  values explicitly labeled. INP is the interaction metric — from lab runs use proxy
  (e.g., long-tasks estimate) and label methodology.
- Broken-link sample cap: e.g., first 20 internal links per page, one page deep, configurable.
- Signature table examples: WordPress (wp-content/generator meta), Shopify (cdn.shopify.com),
  Webflow (webflow script), React (root div + react fiber marker), GA4 (gtag), Hotjar etc.
- Re-audit idempotency: same lead + same audit version → new row (history), never overwrite.

</specifics>
