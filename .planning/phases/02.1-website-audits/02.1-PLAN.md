## Phase Goal

**As the** agency owner, **I want to** trigger automated website audits per lead that measure performance/accessibility/SEO/mobile scores, detect tech stack, find broken links and conversion gaps, **so that** I can assess lead quality from a timestamped audit history.

## Acceptance Criteria

| Requirement | Criterion |
|-------------|-----------|
| AUDT-01 | Scores computed from deterministic rule tables (not LLM); CWV measured via Playwright when available, labeled otherwise; INP used (not FID) |
| AUDT-02 | Tech stack, CMS, hosting, analytics detected from signature matching with confidence; rendered + static analysis |
| AUDT-03 | Internal links capped at 20 checked via door; external capped 5; status codes stored; conversion gaps detected by rule patterns |
| AUDT-04 | One `website_audits` row per run; re-audit = new row; newest-first history; alembic 0004 |

## Risks

- Playwright browser not installed → rendered mode degrades to static; tests skip via pytest.mark.skipif
- Robots deny-by-default blocks audit target → runner records FAILED with audit_blocked
- Rate-limit etiquette: shared token bucket + page load from Playwright consumes one acquire; link checks use their own per-domain acquires
- INR lab proxy: labeled as methodology, never conflated with field measurement
- SSRF: URL validation (scheme/ip/port) re-used from enricher.py before any fetch

## Threat Model

| Threat | STRIDE | Mitigation |
|--------|--------|------------|
| SSRF via hostile lead URL | Spoofing | enricher.py URL validation before door fetch; robots deny-by-default limits target set |
| XSS via scraped content in audit pages | Tampering | CMP-06 sanitize before storage; structured view-models; Jinja2 autoescape; no \|safe |
| Crawler abuse of target domains | DoS | Shared token bucket with jitter; link sample caps; external cap 5; single-page scope |
| Audit data integrity | Tampering | Append-only audit events; audit row created at enqueue, status mutated by worker |
