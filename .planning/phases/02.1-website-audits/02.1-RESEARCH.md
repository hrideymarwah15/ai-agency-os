# Phase 02.1: Website Audits — Research

**Researched:** 2026-08-05
**Domain:** per-lead website intelligence auditing (CWV performance, a11y, SEO, mobile; tech/CMS/hosting/analytics detection; broken links; conversion gaps) over the Phase 1/2 compliant fetch door
**Confidence:** HIGH (stack/architecture) / MEDIUM (scoring thresholds, signature table content)

## Summary

Phase 02.1 builds a per-lead website audit pipeline: owner-triggered, enqueued via the Phase 2 outbox pattern, executed by a worker that (1) fetches the lead's site through the compliant door (robots deny-by-default + shared token bucket, D-32), (2) runs a deterministic rule-based analysis producing four 0-100 scores (performance with INP-based Core Web Vitals, accessibility, SEO, mobile) plus tech-stack/CMS/hosting/analytics signature detection, broken-link checks on a capped sample, and missing-form/conversion-gap findings, and (3) persists one `website_audits` row per run with timestamped history (AUDT-04). The UI is Jinja2 SSR (audit list, per-lead history, per-audit detail) with zero JS, reusing Phase 1/2 view-model and design-token patterns.

**Two-mode architecture is the core recommendation.** Mode 1 — *static analysis* — runs always and is fully deterministic/zero-network testable: HTML/headers/robots/sitemap parsing via a new stdlib `HTMLParser` (mirroring `sanitize.py`), TTFB via a streaming extension of the compliant door, scores from rule tables. Mode 2 — *rendered analysis* — runs only when the Playwright browser is available: JS-rendered DOM for signature/forms/links, real LCP/CLS from `PerformanceObserver`, lab-INP from scripted-interaction `event` timing entries with a long-task proxy fallback, and a 375px-viewport horizontal-overflow mobile check. Every rendered-mode value is labeled with its methodology (D-34: lab estimates are labeled as estimates).

**Playwright 1.61.0 pinned** — verified against the locally cached browser build (chromium-1228 + headless shell + ffmpeg-1011 exactly match `playwright-core@1.61.0/browsers.json`; the latest PyPI release 1.62.0 requires a new chromium-1234 download). It is the ONLY new dependency (D-33). Browser-gated tests use `pytest.mark.skipif` on a launch probe, so CI (which never runs `playwright install`) skips them automatically while the full deterministic suite stays green. slopcheck verdict: `[OK]`.

**Primary recommendation:** one `website_audits` table (status-carrying result row created at enqueue in the same transaction as the `audit.run` outbox event — the Phase 2 trigger pattern verbatim), JSONB for broken_links/tech_stack/cwv/gaps, `0004_website_audit_schema.py` migration, a separate `backend/services/audits/` worker (same shape as `discovery/worker.py`, topic `audit.run`), routes under `/website-audits`, and rule-based scoring with the concrete rubric below. Robots-check-before-Playwright: the static door fetch already yields the robots verdict; the browser render is gated on that verdict and one token-bucket acquire.

- **D-41:** UI: Jinja2 SSR pages — lead audit list + per-audit detail (scores, CWV table, tech stack, broken links, gaps); reuse Phase 1/2 design tokens and page patterns; zero JS.
- **D-42:** Sanitization carry-over (CMP-06/D-27): all scraped content routed through `backend/services/discovery/sanitize.py` before storage/rendering; `|safe` forbidden.

### Pattern 1: Two-Mode Pipeline (static core + gated rendered enhancement)
**What:** the audit runner always executes the static pass; the rendered pass runs only when (a) robots allowed the fetch and (b) the browser probe succeeds. Every CWV field records `{"value", "methodology"}` so "estimated"/"measured"/"not_assessed" is explicit in storage and UI (D-34).
**When to use:** always — this is the D-33/D-34 contract.
**Example (probe + renderer skeleton, adapted from playwright.dev/python/docs):**
```python
# backend/services/audits/renderer.py
def browser_available() -> bool:
    """True when the Playwright chromium executable is launchable (CI skip gate)."""
    from playwright.async_api import async_playwright
    try:
        with sync_playwright() as p:  # or an async probe in an executor
            p.chromium.launch(headless=settings.playwright_headless)
        return True
    except Exception:
        return False

async def render_audit(url: str, *, viewport_width: int = 375) -> dict:
    """Return rendered-DOM signals: CWV, INP estimate, signatures, overflow."""
    async with async_playwright() as p:
        browser = await p.chromium.launch(headless=settings.playwright_headless)
        try:
            page = await browser.new_page(viewport={"width": viewport_width, "height": 812})
            await page.add_init_script(_CWV_OBSERVER_JS)   # PerformanceObserver injection
            await page.goto(url, wait_until="load", timeout=30000)
            await page.wait_for_timeout(2500)              # let LCP/CLS settle
            vitals = await page.evaluate("() => window.__vitals")
            # scripted interactions → INP estimate via event-timing entries
            # overflow: scrollWidth > clientWidth on documentElement
            return vitals
        finally:
            await browser.close()
```
**Robots interplay (recommended reading of D-32 ∩ D-33):** the static pass's door fetch already returns the robots verdict (denial raises `RobotsDeniedError` before any request). Rendered mode is only entered when that verdict allowed the page fetch; the render's single page load consumes one additional token from the same shared per-domain bucket (`await bucket.acquire(domain)` via the door). Sub-resource loads inside the browser render are treated as inherent to a single page render, not as separate crawls — the audit is single-page scope (deep crawling is deferred). This interpretation should be confirmed in discuss-phase (Assumption A3).

### Pattern 2: Trigger → Outbox → Worker (Phase 2 pattern verbatim, D-40)
**What:** the POST endpoint creates the `WebsiteAudit` row (status RUNNING) + `OutboxEvent(topic="audit.run")` + audit log in ONE transaction; the worker never starts a run by other means. Re-audit = another POST → another row (history, never overwrite — D-39 idempotency).
**When to use:** always; identical to `api/discovery.py:360-395` + `discovery/worker.py`.
**Example (trigger body — mirror `backend/api/discovery.py` `run_discovery`):**
```python
@router.post("/lead/{business_id}/run")
async def run_website_audit(request, business_id, _owner=Depends(get_current_owner),
                            session=Depends(get_db)):
    _check_origin(request)
    audit = WebsiteAudit(business_id=business_id, audit_version=settings.audit_version,
                         status=AuditStatus.RUNNING)
    session.add(audit)
    await session.flush()
    session.add(OutboxEvent(topic="audit.run",
                            payload={"audit_id": str(audit.id), "business_id": str(business_id)}))
    await AuditService.record(session, actor="owner", action="audit_triggered",
                              entity_type="website_audit", entity_id=str(audit.id), payload={})
    await session.commit()
    return RedirectResponse(url=f"/website-audits/lead/{business_id}", status_code=302)
```

### Pattern 3: Score Rubrics (deterministic rule tables, D-36)
**What:** every dimension starts at 100 and deducts fixed points per measured signal. Only measured signals deduct; unmeasured ones are never guessed (rendered-only signals appear in the CWV/score detail as "not assessed (static mode)"). Scores are `max(0, 100 - deductions)`; the signal list is stored in `methodology` JSONB for transparency.

**Performance (0-100):** TTFB (door `fetch_stream`): ≤800ms no deduction [CITED: web.dev — TTFB target], 800-1500ms −10, >1500ms −25, fetch failed −100 (status FAILED); HTML bytes >512KB −10, >1MB −20; total asset bytes (script+link+img `src`/`href` sums, sized via door streaming HEAD-style probes, capped at 15 assets) >1.5MB −15, >3MB −30; asset count >40 −10, >80 −20; render-blocking scripts in `<head>` without `async`/`defer` >3 −10; HTML response missing `Content-Encoding` (gzip/br) −5; LCP (rendered) >2500ms −20 [CITED: web.dev LCP threshold]; CLS (rendered) >0.1 −15 [CITED: web.dev]; INP estimate (rendered) >200ms −15 [CITED: web.dev]; no caching headers (`Cache-Control`) on static assets −5.

**Accessibility (0-100):** missing `<html lang>` −15; `<img>` without `alt` — ratio-based −min(30, 30 × missing/total); `<input>`/`<select>`/`<textarea>` without `label`/`aria-label`/`aria-labelledby`/`title` — −min(30, 10 × missing) capped 3; no `<h1>` −15; heading order violation (h2..h6 before h1) −5; `<button>` with empty accessible name −10; `<iframe>` without `title` −5; (rendered) computed color-contrast sample on up to 5 text elements via `getComputedStyle` + WCAG relative-luminance math — failing pairs −10 (labeled "estimated — sampled elements").

**SEO (0-100):** missing `<title>` −20, title >60 chars −5; missing meta description −15; missing `og:title`/`og:image` −10; missing twitter card −5; missing `link[rel=canonical]` −10; no `<h1>` −10, multiple `<h1>` −5; no JSON-LD/structured data −10; robots.txt missing −5, robots denies −10 (already FAILED in practice); sitemap.xml missing −5; `http://` scheme −20 or TLS verify failure −15; (rendered) body text empty in static mode but non-empty rendered (JS-only SPA) −10.

**Mobile (0-100):** missing `<meta name=viewport>` −40; `<table>`/fixed `min-width`/`width` attrs suggesting fixed layout −10 each up to 2; (rendered) horizontal overflow at 375px (documentElement.scrollWidth > clientWidth) −30; (rendered) computed body font-size <16px −10; (rendered) tap-target bounding boxes <44px on sampled links/buttons −10; no `srcset`/`sizes` on images −5.

### Pattern 4: Signature Detection Table (D-38)
**What:** an ordered table of `(category, signal_type, pattern, name, confidence)`. signal_type ∈ {header, html_marker, script_src, meta_generator, cookie}. Matching is deterministic first-match-wins per category for CMS/hosting, and set-union for stack/analytics (a site can run React + jQuery + GA4). Multiple patterns per name (e.g., GA4: `gtag('js'` marker OR `googletagmanager.com/gtag/js` script OR `G-[A-Z0-9]{6,}` in inline script) vote up confidence. Rendered mode re-runs matching over the rendered DOM (SPA frameworks only appear there).

### Pattern 5: Broken Links + Missing Forms (AUDT-03, D-37)
**What:** the analyzer's HTMLParser collects `<a href>` (http/https/mailto excluded), `<img src>`, `<link href>`, `<script src>`; internal = same registered domain (normalize via `normalize_domain` from discovery), external = other domains. Internal links up to `AUDIT_BROKEN_LINK_SAMPLE` (20) checked through the door's streaming status probe; external capped at `AUDIT_EXTERNAL_LINK_CAP` (5) — never burst beyond the per-domain token bucket (each target domain gets its own bucket automatically — that IS the etiquette: same-domain links share the site's bucket, external hosts each start fresh at capacity 1). Status probe: `HEAD` via stream → on 405/403 fallback `GET` with `Range: bytes=0-0` and close; ≤3 re-validated redirect hops (enricher pattern, `backend/services/discovery/enricher.py`); `RobotsDeniedError` → status `"robots_denied"` (recorded, not counted as broken); timeout → `"timeout"`.
**Missing forms / conversion gaps (rule list, D-36):** zero `<form>` elements on the page → `{"kind": "missing_contact_form"}`; form without `action`/`mailto:`/`tel:` target → `{"kind": "form_no_action"}`; no visible CTA link/button containing contact intent (regex: contact|book|quote|demo|request|enquiry|inquiry|schedule) → `{"kind": "missing_cta"}`; no `mailto:`/`tel:` anywhere → `{"kind": "no_direct_contact"}`; no phone number pattern → `{"kind": "no_phone_listed"}`. Rendered mode re-checks forms in rendered DOM (JS-injected forms).
**Pitfall — reuse vs new parser:** do NOT reuse `sanitize._TextExtractor` (it drops script/style and only collects text); the analyzer is a NEW `HTMLParser` subclass collecting starttag attrs (mirroring sanitize's skip/cap/never-raise posture), and every string destined for storage/UI is passed through `sanitize.strip_html_to_text`/`strip_control_tokens` (D-42).

### Anti-Patterns to Avoid
- **Raw fetch outside the door:** any `httpx.AsyncClient.get` on an audit target bypasses robots/bucket (D-32) — every request including robots/sitemap probes and link checks goes through `CompliantHTTPClient`.
- **Per-candidate audit rows:** run-granularity events only (`audit_triggered`, `audit_run_started`, `audit_run_finished`, `audit_blocked`) — never one audit log per broken link (Phase 2 Anti-Patterns).
- **Guessing unmeasured scores:** a signal that cannot be measured in the current mode must be recorded as `not_assessed`, not inferred (D-34 honesty; keeps score derivation deterministic).
- **Storing raw HTML:** never persist the fetched HTML; persist only extracted, sanitized, size-capped signals (CMP-06).
- **Rendering without a robots verdict:** launching Playwright on a robots-denied URL defeats D-32's purpose; the render is gated on the static door fetch result.

## Common Pitfalls

### Pitfall 1: Browser-executable drift breaks the suite
**What goes wrong:** `Error: Executable doesn't exist at ...` when Playwright version and cached browser revision disagree (1.62.0 wants chromium-1234; cache has 1228).
**Why it happens:** Playwright pins exact browser revisions per release; `pip install` never downloads browsers — `playwright install` must be run, and it must match the installed package version.
**How to avoid:** pin `playwright==1.61.0` (matches the machine's cache); if bumped, run `.venv/bin/python -m playwright install chromium` as a documented step; never auto-download in tests.
**Warning signs:** first `renderer` test errors with "Executable doesn't exist".

### Pitfall 2: CI hard-fails without browsers
**What goes wrong:** a Playwright import or launch at module scope fails the whole CI run (ci.yml never runs `playwright install`).
**Why it happens:** browser imports/launches at collection time, or non-skipped browser tests.
**How to avoid:** the launch probe lives in a lazy helper (`browser_available()`), browser tests are `@pytest.mark.skipif`-gated on the probe fixture (D-33), and the renderer degrades to static mode at runtime (never raises at import).
**Warning signs:** CI red on playwright errors; imports of `playwright` at module top of non-gated files.

### Pitfall 3: Robots/bucket bypass through the browser
**What goes wrong:** Playwright fetches a robots-denied URL (deny-by-default violated) or the audit fires dozens of sub-requests without the token bucket.
**Why it happens:** the browser's network stack is outside `CompliantHTTPClient`.
**How to avoid:** render gated on the static door fetch's robots verdict + one explicit bucket acquire for the render; single-page scope only (deep crawling deferred). Confirm interpretation in discuss (Assumption A3).
**Warning signs:** audit completes on a domain whose robots.txt denies our UA.

### Pitfall 4: INP measured as if it were field data
**What goes wrong:** storing a lab INP as if it were a real-user value — misleads scoring and future reconciliation (AUDT-05).
**Why it happens:** INP is interaction-driven; a lab run with no interactions has no real INP.
**How to avoid:** script up to 3 interactions (first link/button/form) and take the max `event`-entry duration; fallback to the max long-task duration as a labeled proxy; ALWAYS store `methodology.inp_estimation` (D-34).
**Warning signs:** `inp_ms` present with `methodology` missing.

### Pitfall 5: Link checking turns into a crawl
**What goes wrong:** sample cap ignored → hundreds of external HEAD/GETs per audit; bucket exhaustion stalls the whole pipeline (shared in-process bucket).
**Why it happens:** naive "check all links found" reading of AUDT-03.
**How to avoid:** enforce `AUDIT_BROKEN_LINK_SAMPLE` (20 internal) and `AUDIT_EXTERNAL_LINK_CAP` (5) in the runner (config-driven, tested); external links beyond cap recorded as `"skipped"` in the stored list.
**Warning signs:** audit duration explodes; discovery runs stall behind audit fetches.

### Pitfall 6: Stale outbox identity map in worker tests
**What goes wrong:** worker tests hang asserting drain because the test session's identity map returns stale PENDING rows (Phase 2 hit this: `test_discovery_worker.py`).
**Why it happens:** worker commits through its own session; test session caches pre-commit state.
**How to avoid:** copy the Phase 2 fix — `session.expire_all()` before polling SELECTs; capture plain UUIDs before expiring.
**Warning signs:** drain assertions timing out; `MissingGreenlet` on sync attr access.

### Common Operation 1: Door streaming extension for TTFB + link status (extends `backend/tools/http_client.py`)
```python
# Source: pattern from backend/tools/http_client.py:41-48 + httpx docs (client.stream)
async def fetch_stream(self, url: str) -> tuple[httpx.Response, float]:
    """Robots-checked, throttled, header-only probe: returns (response, ttfb_ms).

    Uses the streaming API so TTFB = time to response headers; the body is
    NOT read (link status checks, asset sizing). Default `fetch()` untouched.
    """
    if not await self._policy.can_fetch(url):
        raise RobotsDeniedError(f"robots.txt denies fetching {url}")
    await self._bucket.acquire(urlparse(url).hostname or "")
    start = time.monotonic()
    async with self._client.stream("GET", url) as response:
        ttfb_ms = (time.monotonic() - start) * 1000
        return response, ttfb_ms
```

### Common Operation 4: Link extraction parser shape (mirrors `sanitize._TextExtractor`)
```python
# Source: backend/services/discovery/sanitize.py:25-46 (skip/cap/never-raise posture)
class _LinkCollector(HTMLParser):
    """Collect href/src targets + counts; hostile input never raises (CMP-06)."""
    _SKIP = frozenset({"script", "style", "noscript"})
    def __init__(self, base_url: str) -> None:
        super().__init__(convert_charrefs=True)
        self.links: list[str] = []
        self.forms: list[dict] = []
        self.scripts: list[str] = []
        self._base = base_url
    def handle_starttag(self, tag: str, attrs: list[tuple[str, str | None]]) -> None:
        if tag in self._SKIP:
            return
        attrs = dict(attrs)
        if tag == "a" and attrs.get("href", "").startswith(("http://", "https://")):
            self.links.append(attrs["href"])
        elif tag == "img" and attrs.get("src"):
            self.links.append(attrs["src"])
        elif tag == "form":
            self.forms.append({"action": attrs.get("action"), "has_input": False})
        elif tag == "script" and attrs.get("src"):
            self.scripts.append(attrs["src"])
```
