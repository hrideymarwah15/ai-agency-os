# Phase 02.1 — UI Design Contract (Website Audits)

> Visual and interaction contract for the audit surfaces: a per-lead audit list, per-lead history, and per-audit detail (4 dimension scores, INP-based Core Web Vitals with methodology labels, tech stack/CMS/hosting/analytics, broken links, conversion-flow gaps) — a Jinja2 SSR continuation of the Phase 1/2 owner UI (D-41: zero client JS, FastAPI + Jinja2, shared `app.css`; Next.js dashboard remains deferred). **Design-system rule: reuse Phase 1/2 tokens and component primitives verbatim (1-UI-SPEC.md approved; 02-UI-SPEC.md approved — no token overrides, no new colors, no new badge pairs).** The only additions are three mechanical layout primitives (`.score-grid`, `.score-value`, `.score-label`) — the complete CSS delta, documented below. Every status/methodology/link-status state maps onto an existing badge class already shipped in `app.css`.

## Layout Contract

Same shell as Phases 1/2 (top nav + constrained main, `max-width: 960px`, `padding: 32px 16px 48px`). All three pages are single-column:

1. **List page** (`/website-audits`) — fixed order:
   - Page header — Display title "Website Audits" + one-line muted description: "Audit history for discovered leads: performance, accessibility, SEO, and mobile scores."
   - Audits table (one row per lead with ≥1 audit) + limit note below.
   - Empty states per Secondary States (no leads at all vs no audits yet).
2. **Lead history page** (`/website-audits/lead/{id}`) — fixed order:
   - Page header — Display title = business name + muted line = website URL.
   - Action row — "Run audit" / "Re-audit" primary button (POST) + muted 14px note beside it: "Queued audits run in order." (worker serialization; the UI never disables the button — double-submits enqueue serially, Phase 2 pattern).
   - Audit history table (newest first) + limit note, or `.empty-state` (no audits for this lead yet).
3. **Detail page** (`/website-audits/{audit_id}`) — fixed order:
   - Page header — Display title = business name; muted line 1 = website URL; muted line 2 = "Audited {started_at} · version {audit_version}" + status badge; when COMPLETED, muted line 3 = "Analysis: Rendered (Playwright)" or "Analysis: Static only".
   - Action row — "Re-audit" primary button + "Queued audits run in order." note.
   - For RUNNING: muted note "This audit is still running. Scores appear here when it completes." — result sections omitted.
   - For FAILED: muted note "The audit failed: {last_error}" (escaped) — result sections omitted.
   - For COMPLETED, sections in this fixed order: **Scores** (4 score cards) → **Core Web Vitals** (table) → **Tech stack, hosting & analytics** (detail list) → **Broken links** (table) → **Conversion-flow gaps** (detail list) → **Audit history** (older audits strip) → footer audit-ID line.
   - Sections separated by 32px (`--space-xl`); section headings carry 16px bottom gap to their content.

The 960px shell is kept — wide tables (broken links, history) scroll horizontally inside `.table-scroll` rather than widening the page (desktop tool, Phase 1/2 rule). The score grid is the page's widest fixed element and is capped by the shell.

Nav order (base.html): **Discovery · Audits · Approval Queue · Audit Log** — "Audits" sits after "Discovery" (both are pipeline-intelligence views); the pending-count badge behavior and the log-out POST are unchanged. All three audit templates set `active_page == 'audits'`.
