Final SPIDR slice of the Discovery phase (after 02 collection and 02.1 audits): given per-lead audit results (tech stack, scores, CWV, gaps, conversion-flow findings), the system detects automation and AI opportunities per industry, estimates ROI for each, computes a weighted 0-100 lead score with priority ordering, and surfaces the prioritized queue in the dashboard pipeline view. <decisions>
## Implementation Decisions

### Opportunity Detection (OPP-01, OPP-02)
- **D-47:** Automation opportunities detected via deterministic pattern rules (SPEC-002 §5.4 table): industry → pattern → recommendation mapping (e.g., Restaurant → no online booking → Booking Automation). Rules are encoded as config-driven rule objects; no LLM.
- **D-48:** AI opportunities detected via deterministic heuristics (SPEC-002 §5.5 table): signal → detection method → recommendation (e.g., no chatbot → DOM analysis → Customer Support Bot). Encoded as marker rules over audit results (tech stack, gaps, content analysis).
- **D-49:** Each detected opportunity carries: name, category (automation/ai), recommendation, estimated ROI, confidence, source audit signals. Stored as JSONB on the lead or a related opportunities table.

### ROI Estimation (OPP-03)
- **D-50:** ROI = (time_saved_hours × hourly_cost × frequency) - implementation_cost_estimate. Hourly cost by industry/size bucket; time_saved from pattern rules; implementation_cost from rule templates. All deterministic config-driven; no LLM.
- **D-51:** Each opportunity ranked by ROI descending within the lead; lead-level opportunity summary includes top 3 by ROI.

### Lead Scoring (SCOR-01)
- **D-52:** Weighted 0-100 score per SPEC-002 §5.6 rubric (total 100%):
  - Website Quality (20%): performance, accessibility, SEO, UX, design scores from audit
  - SEO Maturity (15%): technical SEO, content, authority, local SEO
  - Growth Signals (20%): hiring, funding, traffic growth, social growth, new locations
  - Company Size (15%): employees, revenue, funding (sweet spot 10-200)
  - Automation Potential (15%): manual processes detected, repetitive workflows, scale
  - AI Potential (10%): chatbot missing, FAQ missing, knowledge base missing, support volume
  - Budget Estimate (5%): industry benchmarks, company size, growth stage
- **D-53:** Scores normalized 0-100; tier classification: Hot (80+), Warm (60-79), Cold (40-59), Raw (<40).
- **D-54:** Weights configurable per service vertical (D-52); score breakdown stored for transparency.

### Priority Queue & Dashboard (SCOR-02, DASH-02 continued)
- **D-55:** Priority queue = leads ordered by score desc, then ROI desc, then recency. Surfaced in the dashboard pipeline view (Jinja2 SSR, zero JS, Phase 1/2 tokens).
- **D-56:** Dashboard shows: lead name, industry, score, tier badge, top 3 opportunities with ROI, last audit date, pipeline stage badge. Filters by tier, industry, score range.
- **D-57:** Zero new dependencies. Reuses Phase 2 discovery models (BusinessLead), Phase 02.1 audit models (WebsiteAudit), Phase 1/2 UI patterns.

### Research Resolutions (02.2-RESEARCH.md open questions)
- **D-58 (A1):** Phase 02.1 worker emits `audit.completed` outbox event on successful audit completion; opportunity worker subscribes to `audit.completed` topic and triggers re-scoring.
- **D-59 (A2):** Industry normalization via alias map in config YAML mapping source values to bucket keys (e.g., "Restaurant" → "restaurant", "Food Service" → "restaurant").
- **D-60 (A3):** Dashboard extends `/discovery` (single pipeline view) with tier badges and opportunity columns; no new route needed.
- **D-61 (A4):** Vertical-specific weights deferred to Phase 3; single default weight set per D-52 used here.

## Specific Ideas

- Opportunity rules table driven by a JSON/YAML config file for easy iteration without code changes.
- Score breakdown stored as JSONB per lead for drill-down UI.
- Lead tier badges: Hot (red), Warm (amber), Cold (blue), Raw (slate) — map to existing badge pairs.
- Pipeline view reuses discovery.html table structure + adds opportunity columns + tier badges.
- No LLM anywhere in this slice — all deterministic rules, config-driven, fully testable.
- ROE rules: if lead has no audit yet, score = 0, tier = Raw, appears at bottom of queue.
