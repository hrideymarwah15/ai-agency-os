## Phase Goal

**As the** agency owner, **I want to** see each lead ranked with detected automation and AI opportunities, ROI estimates, and a weighted 0-100 score, **so that** I can work the priority queue of qualified leads in the sales pipeline.

## Acceptance Criteria

| Requirement | Criterion |
|-------------|-----------|
| OPP-01 | Automation opportunities detected via industry→pattern rules (config-driven, deterministic) |
| OPP-02 | AI opportunities detected via signal→heuristic rules (config-driven, deterministic) |
| OPP-03 | Each opportunity has ROI estimate: (time_saved × hourly_cost × freq) - impl_cost |
| SCOR-01 | Weighted 0-100 lead score from 7 factors (D-52), tier: Hot≥80/Warm≥60/Cold≥40/Raw<40 |
| SCOR-02 | Priority queue: score desc → ROI desc → recency; dashboard shows tier, score, top 3 opps |

## Risks

- Rule YAML condition compilation: malformed lambdas → syntax errors at load time; test fixtures validate all rules
- Industry normalization: source values may not match bucket keys exactly; alias map in YAML handles this
- Dashboard route: extends /discovery (single pipeline) — no new route conflicts
- Vertical weights deferred to Phase 3 — single default weight set used here

## Threat Model

| Threat | STRIDE | Mitigation |
|--------|--------|------------|
| SSRF via rule config URL | Spoofing | Rule YAML loaded from local filesystem only; no external fetches |
| XSS via opportunity content | Tampering | All opportunity strings sanitized via discovery/sanitize.py; structured view-models; no \|safe |
| Auth bypass on dashboard | Spoofing | Owner-only via get_current_owner; _check_origin on POST |
| Score manipulation | Tampering | All scoring deterministic, server-side only; no client-side score computation |
