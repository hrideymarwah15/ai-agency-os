# Phase 02.2: Opportunities and Scoring - Research

**Researched:** 2026-08-07
**Domain:** deterministic opportunity detection (automation + AI) from audit signals, ROI estimation, weighted lead scoring (0-100), priority queue, Jinja2 SSR pipeline dashboard
**Confidence:** HIGH (architecture/patterns) / MEDIUM (rule table content, scoring thresholds)

## Summary

Phase 02.2 is the final Discovery slice: given per-lead `WebsiteAudit` results (tech stack, 4 dimension scores, CWV, gaps, conversion-flow findings) from Phase 02.1, the system (1) detects automation opportunities via industry→pattern config rules, (2) detects AI opportunities via signal→heuristic rules over audit results, (3) estimates ROI per opportunity using a deterministic formula `(time_saved × hourly_cost × frequency) - impl_cost`, (4) computes a weighted 0-100 lead score across 7 factors (100% total) with tier classification (Hot/Warm/Cold/Raw), (5) maintains a priority queue ordered by score↓ → ROI↓ → recency, and (6) surfaces the pipeline in a Jinja2 SSR dashboard extending the Phase 2 `discovery.html` pattern. No LLM, all deterministic config-driven rules, zero new dependencies.

**Primary recommendation:** Implement a pure-Python rule engine (`services/opportunities/`) with hot-reloadable YAML config for automation/AI rules, a scorer service that reads `Business` + latest `WebsiteAudit`, a queue service that orders leads, and a new dashboard route/template under `/discovery` (or `/opportunities`) reusing the discovery table structure. Trigger re-scoring via outbox event `audit.completed` from Phase 02.1 worker.

### Pattern 1: Rule Engine (Config-Driven Pattern Matching)
**What:** A YAML file defines two rule tables — automation rules (industry → pattern → recommendation) and AI rules (signal → detection method → recommendation). The engine loads rules at startup, watches the file for changes (hot-reload via `mtime` check), and evaluates each rule against `Business` + latest `WebsiteAudit` signals. Each rule object: `{name, category, condition_fn, recommendation, roi_params, confidence}`. Conditions are pure Python lambdas or operator expressions over audit JSONB fields (tech_stack, gaps, scores, cwv, industry, employee_count).

**When to use:** Always — this is the D-47/D-48 contract. No LLM, fully deterministic, testable with fixture data.

**Config Schema (rules.yaml):**
```yaml
# Automation rules: industry → pattern → recommendation
automation_rules:
  - name: "booking_automation"
    industry: ["Restaurant", "Clinic", "Coaching", "Hospitality"]
    pattern: "no_online_booking"
    detection:
      gaps_contains: ["missing_contact_form", "missing_cta", "no_direct_contact"]
      tech_stack_excludes: ["calendly", "square", "toast", "opentable", "resy"]
    recommendation: "Booking Automation (WhatsApp/Web)"
    category: "automation"
    roi_params:
      time_saved_hours_monthly: 20
      frequency_monthly: 1
      impl_cost_estimate: 15000  # INR, from rule template
    confidence: 0.85

# AI rules: signal → detection → recommendation
ai_rules:
  - name: "customer_support_bot"
    signal: "no_chatbot"
    detection:
      tech_stack_excludes: ["intercom", "drift", "hubspot", "zendesk", "crisp", "tawk", "freshchat"]
      gaps_contains: ["missing_contact_form"]
    recommendation: "Customer Support Bot"
    category: "ai"
    roi_params:
      time_saved_hours_monthly: 40
      frequency_monthly: 1
      impl_cost_estimate: 35000
    confidence: 0.80
  - name: "faq_assistant"
    signal: "no_faq"
    detection:
      content_check: "faq_keyword_absent"  # static analyzer signal
    recommendation: "FAQ Assistant"
    category: "ai"
    roi_params:
      time_saved_hours_monthly: 10
      frequency_monthly: 1

    confidence: 0.75

# backend/services/opportunities/roi.py
class ROICalculator:
    def __init__(self, hourly_buckets: dict, impl_templates: dict):
        self.hourly_buckets = hourly_buckets
        self.impl_templates = impl_templates

    def calc_roi(self, opp: dict, business: Business, audit: WebsiteAudit) -> float:
        """Return monthly ROI in INR (can be negative)."""
        time_saved = opp["roi_params"]["time_saved_hours_monthly"]
        freq = opp["roi_params"]["frequency_monthly"]
        impl_cost = opp["roi_params"].get("impl_cost_estimate") or \
                    self.impl_templates.get(opp["name"], 0)
        industry = business.industry or "Unknown"
        size_bucket = self._size_bucket(business.employee_count)
        hourly_cost = self.hourly_buckets.get(industry, {}).get(size_bucket, 1000)
        return (time_saved * hourly_cost * freq) - impl_cost

    def _size_bucket(self, employee_count: int | None) -> str:
        if not employee_count:
            return "Micro"
        if employee_count <= 10: return "Micro"
        if employee_count <= 50: return "Small"
        if employee_count <= 200: return "Medium"
        if employee_count <= 1000: return "Large"
        return "Enterprise"
```

### Pattern 3: Lead Scorer (Weighted Rubric Implementation)
**What:** 7-factor weighted score (100% total) per D-52. Each factor computes a raw 0-100 sub-score from audit/business signals, multiplies by weight, sums to final 0-100. Tier: Hot≥80, Warm≥60, Cold≥40, Raw<40. Score breakdown stored as JSONB for transparency.

**Factor Details (signals → raw score):**

| Factor (Weight) | Signals (from Business + WebsiteAudit) | Raw Score Logic |
|-----------------|----------------------------------------|-----------------|
| Website Quality (20%) | `audit.performance_score`, `accessibility_score`, `seo_score`, `mobile_score`, `ux_score` (derived) | Mean of available dimension scores; missing = not assessed (excluded from mean) |
| SEO Maturity (15%) | `audit.seo_score`, `audit.gaps` (SEO-related), `audit.cwv`, `business.tech_stack` (analytics) | `audit.seo_score` base; -10 per SEO gap; +5 if GA4/GTM present |
| Growth Signals (20%) | `business.growth_signals` (list), `business.employee_count` trend, `business.rating`/`review_count` trend | Heuristic: each growth signal +10; hiring=+15; funding=+20; rating>4.0=+10; capped at 100 |
| Company Size (15%) | `business.employee_count`, `business.estimated_budget`, `business.funding_stage` | Sweet spot 10-200 employees → 100; <10 → 60; 201-500 → 80; >500 → 70; funded startup bonus +10 |
| Automation Potential (15%) | Count of automation opportunities detected, `audit.gaps` (manual process gaps), `business.pain_points` | Base 30 + 15 per automation opp (max 3); +10 per manual-process gap; capped 100 |
| AI Potential (10%) | Count of AI opportunities detected, `audit.tech_stack` (missing chatbot/analytics/CRM) | Base 20 + 20 per AI opp (max 3); +15 if no chatbot; +10 if no analytics; capped 100 |
| Budget Estimate (5%) | `business.estimated_budget`, `business.industry`, `business.employee_count`, `config.industry_multipliers` | Industry benchmark × size multiplier → budget band; ≥50k INR=100, 20-50k=70, 10-20k=50, <10k=30 |

**LeadScorer Interface:**
```python
# backend/services/opportunities/scorer.py
from dataclasses import dataclass
from typing import Any

@dataclass
class ScoreBreakdown:
    factor: str
    weight_pct: int
    raw_score: int
    weighted_score: float
    signals_used: list[str]

class LeadScorer:
    def __init__(self, weights: dict[str, float]):
        # weights sum to 1.0; keys: website_quality, seo_maturity, growth_signals,
        # company_size, automation_potential, ai_potential, budget_estimate
        self.weights = weights

    def score_lead(
        self,
        business: Business,
        audit: WebsiteAudit | None,
        opportunities: list[dict]
    ) -> tuple[int, str, list[ScoreBreakdown]]:
        """Return (score_0_100, tier, breakdown_list)."""
        if audit is None or audit.status != "COMPLETED":
            return 0, "Raw", [ScoreBreakdown(f, w*100, 0, 0.0, ["no_audit"]) for f,w in self.weights.items()]

        breakdown = []
        total = 0.0
        for factor, weight in self.weights.items():
            raw = self._score_factor(factor, business, audit, opportunities)
            weighted = raw * weight
            total += weighted
            breakdown.append(ScoreBreakdown(factor, int(weight*100), raw, weighted, []))

        score = max(0, min(100, round(total)))
        tier = self._tier(score)
        return score, tier, breakdown

    def _tier(self, score: int) -> str:
        if score >= 80: return "Hot"
        if score >= 60: return "Warm"
        if score >= 40: return "Cold"
        return "Raw"
```

### Pattern 4: Priority Queue Builder
**What:** SQL query ordering leads by `priority_score DESC, total_roi DESC, updated_at DESC`. `total_roi` = sum of opportunity ROIs for the lead. Materialized as a view or computed in the dashboard query.

**QueueBuilder Interface:**
```python
# backend/services/opportunities/queue.py
from dataclasses import dataclass
from typing import Any
from uuid import UUID

@dataclass
class LeadView:
    business_id: UUID
    name: str
    industry: str | None
    priority_score: int
    tier: str
    total_roi: float
    top_opportunities: list[dict]  # top 3 by ROI
    last_audited_at: datetime | None
    pipeline_stage: str  # from Business.status

class QueueBuilder:
    def __init__(self, session: AsyncSession):
        self.session = session

    async def build_queue(
        self,
        *,
        tier_filter: str | None = None,
        industry_filter: str | None = None,
        min_score: int | None = None,
        limit: int = 50
    ) -> list[LeadView]:
        """Ordered pipeline view with optional filters."""
        from sqlalchemy import select, func, desc
        from backend.database import Business, WebsiteAudit

        # Subquery: latest completed audit per business
        latest_audit = (
            select(WebsiteAudit.business_id, func.max(WebsiteAudit.started_at).label("latest"))
            .where(WebsiteAudit.status == "COMPLETED")
            .group_by(WebsiteAudit.business_id)
            .subquery()
        )

        stmt = (
            select(Business)
            .outerjoin(latest_audit, Business.id == latest_audit.c.business_id)
            .order_by(
                desc(Business.priority_score),
                desc(Business.total_roi),  # computed property or JSONB extraction
                desc(Business.updated_at)
            )
            .limit(limit)
        )
        # Apply filters...
        rows = (await self.session.execute(stmt)).scalars().all()
        return [self._to_view(b) for b in rows]
```

### Pattern 5: Outbox Worker for Re-Scoring (Audit Completed → Opportunity Refresh)
**What:** Phase 02.1 audit worker emits `OutboxEvent(topic="audit.completed", payload={"audit_id": ..., "business_id": ...})` on successful completion. Phase 02.2 worker drains this topic, calls `rescore_lead(business_id)`, upserts opportunities + score + tier on `Business` in one transaction.

**Worker Pattern (mirrors `services/discovery/worker.py` and `services/audits/worker.py`):**
```python
# backend/services/opportunities/worker.py
import asyncio
from uuid import UUID
from loguru import logger
from sqlalchemy import select
from backend import database
from backend.database import OutboxEvent, utc_now
from backend.services.opportunities.engine import rescore_lead

_OPPORTUNITY_TOPIC = "audit.completed"
_POLL_INTERVAL_SECONDS = 5.0
_MAX_ERROR_LENGTH = 1000

async def opportunity_worker(*, poll_interval: float = _POLL_INTERVAL_SECONDS) -> None:
    """Drain audit.completed events → rescore lead → upsert opportunities/score."""
    while True:
        try:
            await _process_one()
        except asyncio.CancelledError:
            raise
        except Exception:  # noqa: BLE001
            logger.exception("opportunity worker iteration failed")
        await asyncio.sleep(poll_interval)

async def _process_one() -> bool:
    session_maker = database.async_session_maker
    if session_maker is None:
        raise RuntimeError("Database not initialized")
    async with session_maker() as session:
        result = await session.execute(
            select(OutboxEvent)
            .where(OutboxEvent.topic == _OPPORTUNITY_TOPIC, OutboxEvent.status == "PENDING")
            .order_by(OutboxEvent.created_at)
            .limit(1)
        )
        event = result.scalars().first()
        if event is None:
            return False
        event.status = "IN_PROGRESS"
        event.attempts += 1
        await session.commit()
        try:
            business_id = UUID(event.payload["business_id"])
            await rescore_lead(session, business_id)
        except Exception as exc:  # noqa: BLE001
            event.status = "FAILED"
            event.last_error = str(exc)[:_MAX_ERROR_LENGTH]
            event.processed_at = utc_now()
            await session.commit()
            logger.error("opportunity event {} failed: {}", event.id, exc)
            return True
        event.status = "DONE"
        event.processed_at = utc_now()
        await session.commit()
        return True
```

**Rescore Function (idempotent upsert):**
```python
# backend/services/opportunities/engine.py
async def rescore_lead(session: AsyncSession, business_id: UUID) -> None:
    """Fetch business + latest audit → detect opportunities → calc ROI → score → upsert."""
    from backend.database import Business, WebsiteAudit
    from sqlalchemy import select, func

    business = await session.get(Business, business_id)
    if not business or not business.website_url:
        return

    # Latest completed audit
    audit = (
        await session.execute(
            select(WebsiteAudit)
            .where(WebsiteAudit.business_id == business_id, WebsiteAudit.status == "COMPLETED")
            .order_by(WebsiteAudit.started_at.desc())
            .limit(1)
        )
    ).scalars().first()

    # Run engine
    rule_engine = RuleEngine(settings.opportunity_rules_path)
    roi_calc = ROICalculator(settings.hourly_cost_buckets, settings.impl_cost_templates)
    scorer = LeadScorer(settings.scoring_weights["default"])

    auto_opps = rule_engine.evaluate_automation(business, audit) if audit else []
    ai_opps = rule_engine.evaluate_ai(business, audit) if audit else []
    all_opps = auto_opps + ai_opps

    # Add ROI to each
    for opp in all_opps:
        opp["roi_monthly_inr"] = roi_calc.calc_roi(opp, business, audit)
    all_opps.sort(key=lambda o: o["roi_monthly_inr"], reverse=True)

    # Score
    score, tier, breakdown = scorer.score_lead(business, audit, all_opps)

    # Upsert on Business (JSONB + scalar fields)
    business.opportunities = all_opps
    business.opportunity_version = (business.opportunity_version or 0) + 1
    business.priority_score = score
    business.tier = tier
    business.score_breakdown = [b.__dict__ for b in breakdown]
    business.last_scored_at = datetime.now(UTC)
    business.total_roi = sum(o["roi_monthly_inr"] for o in all_opps)  # computed for queue ordering

    await AuditService.record(
        session, actor="system", action="lead_rescored",
        entity_type="business", entity_id=str(business_id),
        payload={"score": score, "tier": tier, "opportunity_count": len(all_opps)},
    )
    # Caller commits
```

### Anti-Patterns to Avoid
- **LLM in opportunity detection:** D-47/D-48 explicitly forbid LLM; all rules are config-driven deterministic code.
- **Guessing missing audit signals:** If audit is absent or incomplete, score = 0, tier = Raw, opportunities = [] — never infer.
- **Storing raw audit text in opportunities:** Only store structured dicts (name, category, recommendation, roi_monthly_inr, confidence, source_signals).
- **Per-opportunity audit logs:** Run-granularity only (`lead_rescored`); never one audit per opportunity.
- **Hardcoded thresholds in Python:** All weights, buckets, templates in `config.py` or `rules.yaml` — hot-reloadable.
- **New dependencies:** Zero new deps beyond `pyyaml` (transitive). No `numpy`, `pandas`, `scikit-learn`.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Config-driven rule engine | Custom DSL/interpreter | YAML + compiled Python lambdas | Rules are simple predicates; YAML + `eval`-safe compilation is sufficient; no parser needed |
| ROI formula evaluator | Expression parser | Pure Python arithmetic | Formula is fixed `(a*b*c)-d`; just a function |
| Weighted scoring rubric | Generic scoring framework | 7 explicit factor functions | Only 7 factors, fixed weights; explicit code is more readable and testable |
| Priority queue | Redis sorted set / external queue | SQL `ORDER BY` on indexed columns | PostgreSQL indexes on `priority_score`, `total_roi`, `updated_at`; no extra infra |
| Hot-reload config | File watcher daemon | `mtime` check on each request/worker iteration | Low frequency (worker polls every 5s); `os.path.getmtime` is trivial |
| Sanitization of audit-derived text | New scrubber | `sanitize.strip_control_tokens` | CMP-06: prompt-boundary guard already tested; reuse it |

**Key insight:** This phase is pure business logic over shipped data models. Every component is a pure Python function/class with no external I/O (except DB reads/writes). The complexity is in the rule tables and scoring math — not infrastructure.

## Common Pitfalls

### Pitfall 1: Rule Condition Evaluation Errors on Missing Audit
**What goes wrong:** `AttributeError` or `KeyError` when `audit` is `None` or a field like `audit.tech_stack` is missing.
**Why it happens:** Rules assume audit exists; leads without audits enter the pipeline (Raw tier).
**How to avoid:** Every condition helper guards `audit is None` → return `False`. `evaluate_*` returns `[]` if no audit. Scorer returns 0/Raw immediately if no completed audit.
**Warning signs:** Worker logs `AttributeError` on `audit.tech_stack`; leads stuck in Raw with errors.

### Pitfall 2: ROI Calculation Uses Wrong Hourly Cost Bucket
**What goes wrong:** Industry not in `HOURLY_COST_BUCKETS` → KeyError or falls back to wrong default.
**Why it happens:** `business.industry` values from sources may not match config keys exactly (case, spacing, synonyms).
**How to avoid:** Normalize industry in `Business` model (lowercase, alias map). Config buckets use normalized keys. Default bucket `"default"` with safe fallback.
**Warning signs:** ROI values identical across diverse industries; `KeyError` in worker logs.

### Pitfall 3: Score Breakdown JSONB Serialization Fails
**What goes wrong:** `ScoreBreakdown` dataclass with non-JSON-serializable fields (e.g., `datetime`, `Decimal`) breaks upsert.
**Why it happens:** `ScoreBreakdown.__dict__` includes all fields; `dataclass` may have complex types.
**How to avoid:** Use a `to_dict()` method or Pydantic model for breakdown with `model_dump(mode="json")`. Store only primitive types.
**Warning signs:** `TypeError: Object of type Decimal is not JSON serializable` on commit.

### Pitfall 4: Worker Processes Same Audit Event Twice (Idempotency)
**What goes wrong:** `audit.completed` event processed, then worker crashes before commit, event re-queued, lead rescored twice → `opportunity_version` increments but no data change.
**Why it happens:** Outbox pattern marks `IN_PROGRESS` → execute → `DONE`; if crash between execute and `DONE`, event stays `IN_PROGRESS` and may be retried.
**How to avoid:** `rescore_lead` is idempotent (same inputs → same outputs). `opportunity_version` increments each run but that's acceptable. For strict idempotency, add `last_processed_audit_id` on `Business` and skip if unchanged.
**Warning signs:** `opportunity_version` increments rapidly for same lead; audit logs show duplicate `lead_rescored`.

### Pitfall 5: Dashboard Query N+1 on Opportunities
**What goes wrong:** Template loops `lead.opportunities` triggering lazy loads per row.
**Why it happens:** `Business.opportunities` is JSONB column — not a relationship — but if code incorrectly defines a relationship or accesses `lead.audit` without join.
**How to avoid:** Dashboard query selects only `Business` columns; `opportunities` is inline JSONB. No joins needed. Verify with `EXPLAIN ANALYZE`.
**Warning signs:** Dashboard page load >500ms; SQL logs show many queries per request.

### Pitfall 6: Tier Badge CSS Class Mismatch
**What goes wrong:** Template uses `badge--hot` but CSS defines `.badge--failed` for red.
**Why it happens:** Mapping tier→badge class done in Python view model but CSS uses different semantic names.
**How to avoid:** Define mapping in one place (Python `_tier_badge_class(tier)`) and ensure CSS has matching classes. Add missing `.badge--hot`, `.badge--warm`, `.badge--cold`, `.badge--raw` to `app.css`.
**Warning signs:** Tier badges render as plain text (no color) in browser devtools.

### Verified Pattern: Scorer Factor Functions (Zero-Network Unit Testable)
```python
# backend/services/opportunities/scorer.py (factor implementations)
def _score_website_quality(self, business: Business, audit: WebsiteAudit, opps: list) -> int:
    scores = [audit.performance_score, audit.accessibility_score, audit.seo_score, audit.mobile_score]
    available = [s for s in scores if s is not None]
    return round(sum(available) / len(available)) if available else 0

def _score_seo_maturity(self, business: Business, audit: WebsiteAudit, opps: list) -> int:
    base = audit.seo_score or 0
    seo_gaps = sum(1 for g in (audit.gaps or []) if g.get("kind") in ("missing_cta", "no_direct_contact", "missing_contact_form"))
    has_analytics = any(t["name"] in ("ga4", "gtm", "ga") for t in (audit.analytics or []))
    return max(0, min(100, base - 10 * seo_gaps + (5 if has_analytics else 0)))

def _score_growth_signals(self, business: Business, audit: WebsiteAudit, opps: list) -> int:
    score = 30
    for sig in (business.growth_signals or []):
        if sig in ("hiring", "funding", "traffic_growth"): score += 15
        elif sig in ("social_growth", "new_location"): score += 10
    if business.rating and business.rating >= 4.0: score += 10
    if business.review_count and business.review_count > 50: score += 5
    return min(100, score)

def _score_company_size(self, business: Business, audit: WebsiteAudit, opps: list) -> int:
    emp = business.employee_count or 0
    if 10 <= emp <= 200: return 100
    if emp < 10: return 60
    if emp <= 500: return 80
    return 70

def _score_automation_potential(self, business: Business, audit: WebsiteAudit, opps: list) -> int:
    auto_opps = [o for o in opps if o["category"] == "automation"]
    manual_gaps = sum(1 for g in (audit.gaps or []) if g.get("kind") in ("missing_contact_form", "form_no_action"))
    return min(100, 30 + 15 * len(auto_opps) + 10 * manual_gaps)

def _score_ai_potential(self, business: Business, audit: WebsiteAudit, opps: list) -> int:
    ai_opps = [o for o in opps if o["category"] == "ai"]
    has_chatbot = any(t["name"] in ("intercom", "drift", "crisp", "tawk") for t in (audit.analytics or []))
    has_crm = any(t["name"] in ("hubspot", "salesforce", "pipedrive") for t in (audit.analytics or []))
    score = 20 + 20 * len(ai_opps)
    if not has_chatbot: score += 15
    if not has_crm: score += 10
    return min(100, score)

def _score_budget_estimate(self, business: Business, audit: WebsiteAudit, opps: list) -> int:
    budget = business.estimated_budget or 0
    if budget >= 50000: return 100
    if budget >= 20000: return 70
    if budget >= 10000: return 50
    return 30
```
